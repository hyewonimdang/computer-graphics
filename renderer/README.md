# B · 스테레오 표면 렌더러

저장소 루트에서 실행합니다. 먼저 [Python 환경 설정](../README.md#시작하기)을 마치고 KITTI 첫 프레임으로 렌더러 입력을 생성합니다. 이미 A에서 생성한 프레임이 있으면 아래의 FRAME_DIR을 그 경로로 지정하세요.

```sh
(cd stereo_reconstruction && python download_kitti_sample.py --output data/kitti --frames 0 && python kitti_pipeline.py --root data/kitti --frames 0 --output runs/kitti_frame0)
npm ci --prefix renderer
FRAME_DIR=stereo_reconstruction/runs/kitti_frame0/frames/0000000000
mkdir -p renderer/data
cp "$FRAME_DIR/frame.json" "$FRAME_DIR/new_points.bin" "$FRAME_DIR/surface.bin" renderer/data/
python renderer/serve.py
```

브라우저에서 [렌더러 열기](http://127.0.0.1:8724/renderer/). 세 입력 파일은 같은 프레임에서 가져옵니다. 새 점만 저장된 후속 프레임은 그 프레임의 증분만 표시합니다. `serve.py`는 Windows의 기본 `http.server`가 .mjs를 text/plain으로 내보내 ES 모듈 로드가 막히는 문제를 피하기 위한 것입니다.

A의 공식 디코더로 두 payload를 읽고 개수와 point_id 순서를 대조합니다. 위치와 법선은 (X,−Y,−Z)로 변환하며 반경은 미터 그대로 사용합니다.

### 직접 구현한 것과 Three.js가 하는 것

| 영역 | Three.js | 직접 구현 (파일) |
|---|---|---|
| 그래픽스 API | WebGL 초기화, GPU 버퍼·렌더 타깃(FBO)·깊이 텍스처 생성, 드로 호출 | 모든 GLSL 셰이더(RawShaderMaterial이라 Three의 행렬·카메라 uniform을 쓰지 않음), 렌더 패스 순서 (`splats.js`, `effects.js`) |
| 변환·카메라 | 행렬 값을 복사해 넣는 `THREE.Camera` 껍데기만 | K_rect 기반 투영 행렬, lookAt 뷰 행렬, 역행렬, 직교 투영, 오빗 카메라와 포인터 입력 (`camera.js`) |
| 표면 표현 | — | 법선 방향 원판 splat, 원형 경계 discard, 다중 패스 가우시안 블렌딩, 주변 간격 반경 (`splats.js`, `effects.js`, `spacing.js`) |
| 조명·그림자 | — | Blinn-Phong, 젖음→마름 재질, Shadow Mapping (광원 시점 직교 깊이 패스 + 3×3 PCF), 한 발 해석적 투영 그림자 |
| 후처리·디버그 | — | EDL, 패스별 디버그 뷰 2×2, FPS·점 개수 비교 |

카메라는 frame.json의 K_rect에서 투영 행렬을 만들고 (픽셀 중심 +0.5, v 아래 방향을 NDC +y 위로 뒤집음), 카메라 포즈를 F·T·F (F = diag(1,−1,−1,1))로 뷰어 좌표에 옮겨 초기 시점을 잡습니다. 드래그 회전, 휠 거리, 오른쪽 드래그(또는 Shift+드래그) 이동, 카메라 초기화를 지원합니다. 깊이 항은 표준 OpenGL 규약이라 effects.js의 하드웨어 깊이 → 거리 복원과 맞습니다.

splats.js의 GLSL은 각 인스턴스의 접평면과 원형 경계, 확산광과 정반사를 계산합니다. 법선 모드의 RGB는 뷰어 월드 좌표의 단위 법선을 [0,1]로 매핑한 값입니다. 무효 법선은 모든 모드에서 원래 색의 작은 점으로 표시합니다.

### Shadow Mapping
체크하면 매 프레임 광원 시점에서 먼저 깊이만 그립니다. 광원은 방향광이므로 장면 경계 구를 덮는 직교 투영을 쓰고, 2048² 깊이 텍스처에 기록합니다. 점군은 틈이 많아 캐스터 원판만 3배로 키워 그림자가 체처럼 새는 것을 줄입니다. 조명 splat 모드의 프래그먼트는 월드 위치를 광원 클립 공간으로 옮겨 저장된 깊이와 비교하고, 3×3 PCF로 경계를 부드럽게 한 뒤 확산광과 정반사에 곱하며 그늘에서는 주변광도 절반으로 줄입니다. 기울기 비례 bias로 자기 그림자(acne)를 줄입니다.

광원 방위 슬라이더는 0°가 카메라 뒤, ±180°가 장면 앞쪽이고, 광원 높이 슬라이더로 고도를 정합니다. 카메라 뒤 높은 광원에서는 가리는 물체가 거의 없어 그림자가 약하므로, **그림자 시연 버튼**(앞쪽 150°, 높이 0.25)으로 긴 그림자가 도로에 드리우는 상태를 바로 볼 수 있습니다. 디버그 뷰를 함께 켜면 왼쪽 위 칸에 광원 시점 깊이(그림자 맵)가 표시됩니다.

### 패스별 디버그 뷰와 지표
디버그 뷰를 켜면 화면을 넷으로 나눠 왼쪽 위 최전면 깊이(가까울수록 밝음, 40 m 기준), 오른쪽 위 법선 버퍼, 왼쪽 아래 블렌딩 누적 가중치, 오른쪽 아래 최종 합성을 보여줍니다. 점 개수 선택은 point_id 해시로 점의 1/2, 1/4만 남겨 FPS 변화를 비교합니다. FPS는 0.5초 간격으로 갱신됩니다.

URL 쿼리로 컨트롤을 미리 설정할 수 있습니다. 예: `renderer/?shadowMap=1&debug=1&blend=1&time=4.3`, `renderer/?paint=1&style=gun&time=4.3`. 시연 링크나 자동 캡처에 씁니다.

C의 paint.js가 착지 시각과 비행 시간을 정하면 viewer.js가 타임라인을 갱신하고 splats.js의 셰이더가 비행과 착지, 건조를 계산합니다.

### 표면 효과 비교
일시정지 후 조명 splat 모드에서 비교합니다. 세 체크박스는 각각 독립적이며 기본값은 꺼짐입니다. 확대는 유효한 원판 반경에만 1~3배를 곱합니다. 블렌딩은 가장 앞의 깊이를 먼저 구한 뒤 그 표면에서 1.5 cm 또는 깊이의 0.3% 중 큰 값 이내인 조각의 선형 RGB를 중심 가중 평균합니다. EDL은 주변 네 방향의 깊이 차이로 뒤쪽 표면을 어둡게 합니다. 배경은 음영 계산에서 제외합니다. 두 후처리는 단일 샘플 렌더 타깃을 사용하므로 기본 화면과 실루엣의 안티앨리어싱이 조금 다릅니다. 원본 점 좌표와 반경 데이터는 그대로 유지합니다.

주변 간격 기반 반경을 켜면 고정 확대를 일시 대체합니다. 끄면 이전 고정 배율 설정으로 돌아갑니다. 강도 0%는 원래 반경, 100%는 추정 반경이며 사이 값은 선형 보간합니다. 정류 UV 반경 8픽셀에서 깊이와 접평면을 검사하고 법선이 유사한 세 방향 이상의 이웃 간격으로 반경을 추정합니다. 관측된 깊이 단차까지의 거리와 원래 반경의 4배로 추가 확대를 제한합니다. 이웃이 부족하거나 법선이 없으면 원래 표현을 유지합니다. 미관측 영역의 경계까지 보장하지는 않습니다.

페인트 연출에서 붓질을 켜면 빈 화면에서 시작합니다. 정류 영상의 아래쪽부터 다섯 번 왕복하며 각 점의 원래 RGB와 XYZ로 장면을 그립니다. 입자는 붓끝 가까이에서 짧게 이동해 표면에 퍼지고 광택이 마릅니다. 시간 슬라이더로 되감거나 초반·중간·완성 버튼으로 이동할 수 있으며 10초에서 완성 화면을 유지합니다.

페인트총을 선택하면 재생이 처음부터 시작됩니다. 오른쪽 아래의 고정 총구에서 처음 여섯 발을 천천히 쏜 뒤 연사하여 장면을 채웁니다. 착지한 물감은 잠시 크게 퍼졌다 원래 크기로 가라앉습니다. 두 방식 모두 시간 슬라이더로 되감을 수 있습니다.
페인트총의 마지막 한 발은 8.10초에 출발해 9.50초에 도로에 닿습니다. 도로 위 한 발 버튼으로 멈춘 뒤 광원 위상을 바꾸면 조명과 투영 그림자가 함께 이동합니다. 착지점 접평면과 광선의 교차 위치를 구해 그 주변의 이미 그려진 같은 방향 표면에만 부드러운 음영을 적용합니다.
